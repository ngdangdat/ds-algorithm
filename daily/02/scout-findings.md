## 7. Two Sum — Line-by-Line Issues for Grading

File: `daily/02/02-leetcode-1/main.go`

```go
func twoSum(nums []int, target int) []int {
    res := make([]int, 2)       // ⚠️ Pre-allocates [0,0]
    numIndexMap := make(map[int]int)
    for idx, n := range nums {
        complement := target - n
        index, ok := numIndexMap[complement]
        if ok {
            res[0] = index
            res[1] = idx
            break
        } else {                // ⚠️ Unnecessary else (break above)
            numIndexMap[n] = idx
        }
    }
    return res                  // ⚠️ Returns [0,0] if no solution
}
```

**Issues a teacher would flag**:
1. **Line 4 — `res := make([]int, 2)`**: Pre-allocating with zero values. If no solution exists, returns `[0, 0]` which is indistinguishable from a valid answer `[0, 0]`. Better: `var res []int` with `append` or return `nil` on no match.
2. **Line 11 — unnecessary `else`**: The `break` on line 10 makes the `else` branch dead code — the code following the `if` block would only execute when `ok` is false regardless. Minor style issue.
3. **Algorithm is correct**: Single-pass hash map, O(n) time, O(n) space — optimal.
4. **Tests pass** (all 3 cases green) but edge cases are untested (empty input, no solution).

**Why current grade is B**: Correct algorithm with minor code quality issues. Appropriate.
