Max Segment Tree

Point update + range-max, both in O(log n). The visual guide for LeetCode 3161.

1. The one-sentence idea

A segment tree is one flat array of ints. The second half holds your real values (the leaves); the first half holds range maxes that let a query skip whole chunks instead of scanning. Think of a sports tournament: each match's winner (the bigger number) advances, and the champion is the overall max.

Why it's fast

  • Query a range: grab whole subtrees that sit fully inside — read one summary, don't descend. Only the 2 edges of the range force splits → ~2·log n nodes.
  • Update one element: only the path from that leaf up to the root changes (log n nodes). Sibling subtrees are independent and untouched.

Index math (1-indexed, root = 1)

  • element i → leaf slot n + i
  • left child = 2·i, right child = 2·i + 1
  • parent = i / 2 (integer division)
  • nodes[i] = max(nodes[2i], nodes[2i+1])

3. How this maps to the obstacle problem

  • Array index = a (coordinate-compressed) position on the number line.
  • Value at a position = gap[p] = p − (nearest obstacle to its left); 0 where there's no obstacle. Each gap is owned by the obstacle on its right edge — so no double counting.
  • Type-2 query [2,x,sz] = max(A, B) ≥ sz where A = MaxRange(0, indexOf(x)) (biggest gap between obstacles both ≤ x) and B = x − floor(x) (trailing gap from last obstacle out to x — handled outside the tree).
  • Type-1 insert at p: Set(p, p−L), and if a right neighbor R exists, Set(R, R−p) (its gap shrinks — the decrease only a segment tree, not a Fenwick-max, can do).
